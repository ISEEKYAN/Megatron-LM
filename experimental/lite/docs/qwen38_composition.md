# Qwen3.8-Flash-Next text training composition

The text model supports random initialization and same-topology native checkpoint training. Parallel acceptance is limited to the explicitly tested configurations; PP, full HF loading/export, full-scale capacity, and end-to-end independent-model parity remain unvalidated. The component evidence below records earlier milestones; the real-data section records the subsequent training acceptance.

## Real-data scratch training

**Random initialization; no pretrained weights loaded.** The reduced official configuration retains all 48 decoder layers (36 GDN and 12 QSA), four HC streams, the PLE placement and 16 hash heads, and the 248320-token vocabulary. Width is 128, with 16 experts/top-10, expert/shared widths 128, six QSA query heads/two KV heads, GDN key/value heads 2/6, 128-dimensional heads, HC low rank 16, and QSA index budget 32. PLE uses explicitly reduced prime buckets.

The official tokenizer selects 128 complete GSM8K training examples of 114–254 tokens, without truncation. Fifty updates use global batch four and deterministic sample ordering. The reported objective averages assistant-token cross-entropy within each document, then averages documents, combining CP contributions where applicable. This is a training-path check, not pretrained-model quality or full-capacity acceptance.

The original overlapping CP2/EP2 run stopped at its first update: one FP32 main-gradient coordinate in `layers.41.linear_attn.A_log` differed by `2^-23` (relative difference `1.655629e-3`, 16384 FP32 ULP). Identical gate inputs followed different backward graphs because `torch.compile` first specialized length 256, then recompiled symbolically after length 240. Consequently, a later length-256 call used a different graph even within one training process.

The first unequal output was the FP32 partial-sum buffer of Inductor's `triton_red_fused__to_copy_add_exp_mul_neg_softplus_softplus_backward_sum_1`. Both paths reduced the same 256 terms per head, split into two 128-term blocks, using FP32 and the same reduction tree. Their two-term lane accumulations differed: static code contracted multiplication/addition into FMA; a symbolic mask separated them in dynamic code. An independent exact-rounding simulation reproduced all six captured partial sums bitwise on each path. For the affected coordinate, their final FP32 sums were `3.8027756090741605e-5` and `3.802776336669922e-5`; the latter is exactly a BF16 rounding midpoint. Rounding to BF16 produced a `2^-22` gap before distributed reduction. For this kernel, the captured BF16/FP32 inputs and the validated length family, this is a mathematically equivalent compiler rounding difference, with observed optimizer consequences: in a ten-update diagnostic continuation, FP32 master parameters differed at update 1, the BF16 model first differed at update 5 (`A_log[1]`: `-0.012451171875` versus `-0.01251220703125`), and loss first differed at update 6 by `2.8014183044433594e-5`. Update-10 loss difference was `-0.00025343894958496094`. The initial perturbation propagated into model state and loss over subsequent updates; the absolute loss gap did not grow monotonically at every step. Without pinning the compilation policy, equivalent training recipes with different compilation histories can follow diverging trajectories. Identical histories still reproduced themselves. These observations do not establish long-run quality impact.

`GatedDeltaNet._compute_g_and_beta` now uses `torch.compile(dynamic=True)` from its first call. Symbolic compilation is the execution standard for this gate; the equations and dtypes are unchanged. This deliberately prioritizes consistency across variable-length training over single-operation precision: FMA performs one rounding and can be more accurate than separate multiply/add, but pinning the dynamic policy adopts the execution regime already reached by variable-length training from its first call. Pinning static compilation would retain separate specializations for each length. The selected policy avoids the observed automatic static-to-dynamic switch; it does not claim dynamic code is more accurate. The scope is repeatability for the tested length changes with fixed tensor layout, dtype, compiler, and GPU; it is not bitwise portability across compiler versions or a new precision contract for other kernels. Disabling the JIT fuser still selects eager execution; older PyTorch versions retain the existing TorchScript fallback.

Reference inspection: [FLA](https://github.com/fla-org/flash-linear-attention/tree/516143e31fce09925e6c39ac37148444bad176c4) and [Automodel](https://github.com/NVIDIA-NeMo/Automodel/tree/8a646a739d30ed99ac022e39541e7db8c35ab2db), fetched 2026-09-14 10:48 UTC; [PyTorch](https://github.com/pytorch/pytorch/tree/07c6e1788caa2d8e0e1b65b46fb6456dcefd813f), fetched 2026-09-14 11:17 UTC. No matching upstream gate fix was identified; this is a local compilation-policy change informed by [PyTorch's dynamic-shape behavior](https://docs.pytorch.org/docs/main/user_guide/torch_compiler/torch.compiler_dynamic_shapes.html). The synthetic GPU regression compares all gate outputs and input gradients before and after `256→240→144→256` length history over 16 fixed seeds, including BF16 midpoint-sensitive gradients. The original implementation fails this assertion at seed 0; the pinned implementation passes all 16 seeds. A subsequent CP2/EP2 real-data run completes all 50 updates with the original zero-tolerance assertions and checkpoint/export checks; this is measured parity after pinning, not an assumption derived from the setting. An [independent repeat](https://wandb.ai/megatron-core-moe-dev/qwen38-realdata/runs/jnqyvnoc) also passes all 50 updates. Across runs, all 50 loss/norm values and the saved update-25/update-50 model, optimizer (including master parameters/moments), active export, and Torch/CUDA/tracker RNG states match bitwise. Python/NumPy RNG states differ and are separately reported; entire checkpoint files are not claimed identical. Intermediate model states were not saved at every update for cross-run comparison.

Each tested run uses paired native runtimes with identical initial state, input, physical parameter sharding, and DDP bucket geometry. An independently written PLE lookup uses all-gather for owner requests and weights; its adjoint preserves source-rank/query order and native embedding arithmetic. It cannot call the production owner lookup. Logits, losses, FP32 DDP gradient buffers, gradient norms, and updated model state must match with zero tolerance at every step. The reference shares the model backbone, optimizer, and DDP implementation; these results do not establish independent-model parity or bitwise equality between different topologies.

At updates 25 and 50, native checkpoints are saved, model parameters are cleared, and restoration is checked byte-for-byte against both model and optimizer state. Native `runtime.export_weights` parameter streams are also saved with a buffer sidecar for each rank, then parameters and buffers are cleared and restored byte-for-byte. Here, active export means this same-topology native artifact; it does not establish HF export, archive completeness, or resharding support. Training continues after the midpoint restoration.

W&B is online throughout training. Execution uses the existing native runtime and distributed optimizer without VERL or Ray. The historical EP router `[3,75]` residual remains separately unresolved; this same-layout comparison does not reclassify it. Existing unsupported-combination guards remain in place.
